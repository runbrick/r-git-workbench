# Git 客户端产品与交互规格

版本：草案 0.1  
状态：Rebased parity 产品基线；实现固定采用 Go + Viva + 系统 Git CLI
目标用户：熟悉 IntelliJ IDEA Git 集成、希望使用独立 Git 图形客户端的开发者

## 1. 产品目标

提供一个以 Rebased（`D:\privateProject\rebased`）为行为与视觉基准的独立 Git 桌面客户端。除替换 Rebased 品牌标识外，主窗口布局、Git 视图、操作入口、工作流、设置和用户可见行为均以一一对应为目标；不可避免的平台差异必须记录并单独验收，不得据此缩减功能范围。

实现必须使用 Go + Viva 绘制原生桌面 UI，并只通过系统 `git` 子进程执行 Git 操作；不得链接 Git 库或引入 WebView。不得复用 IntelliJ 平台代码作为运行时依赖。Rebased 的完整 IDE 平台不属于复刻范围，但随产品提供的 Git、GitHub、GitLab、Terminal、TextMate 等用户可见功能必须进入能力盘点；逐项决定原生实现、等价集成或经用户明确接受后排除，并记录理由。品牌图标与名称替换为本产品标识。

### 产品原则

- Git 命令行是 Git 操作的最终语义来源。客户端应调用系统 Git，尊重仓库和用户的 Git 配置，并显示操作结果。
- 不静默丢弃数据。重置、丢弃、覆盖、强制推送等有损操作必须显示影响范围，并在执行前要求明确确认。
- 主要操作可通过键盘完成；快捷键可搜索、可修改，默认键位尽量贴近 IntelliJ IDEA。
- 一个仓库的工作区改动、暂存区、提交历史和远端状态要清晰区分。
- 长时间操作显示进度，可取消时提供取消入口；操作完成后刷新受影响的数据。
- UI 文字使用用户熟悉的 Git 术语，并区分本地分支、远程跟踪分支和远端。
- Rebased parity 是验收要求，不是设计灵感；截图、交互和功能清单需按固定版本基线逐项对照。

## 2. 产品范围

### 首发必须支持

- 打开本地仓库、最近项目、克隆仓库；识别仓库根目录和 Git 可执行文件。
- 查看工作区状态：已修改、已暂存、未跟踪、已删除、冲突文件。
- 逐文件或逐块暂存、取消暂存、查看文件差异、恢复工作区文件。
- 提交、提交并推送、Amend 上次提交；提交消息模板和最近使用的提交消息。
- 查看提交图、提交详情、提交涉及的文件和文件差异；按分支、作者、路径、消息和日期过滤历史。
- 创建、切换、重命名、删除本地分支；查看远程分支；设置上游分支。
- Fetch、Pull、Push；跟踪 ahead/behind 状态；支持常规推送和有明确保护的强制推送。
- Merge、Rebase、Cherry-pick、Revert；展示操作进度和结果。
- 冲突文件列表、三方合并视图、逐冲突接受当前/传入/两者/手工编辑，继续或中止冲突操作。
- Stash：保存、查看、应用、弹出和删除；应用时进入冲突解决流程。
- Git 设置：可执行文件路径、全局/仓库配置查看、提交身份检查、默认远端、Pull 策略、代理 Git 命令选项。
- 操作日志：展示最近执行的 Git 命令、退出状态和错误输出，便于诊断失败。

### 后续可加入

- Rebased 基线外的扩展功能（例如更广泛的仓库托管平台 API、平台专属审查能力）须进入 parity 清单后再决定是否属于首发。

### 明确不做

- IDE 编辑器、语法高亮、代码补全、重构、代码检查、运行/调试、构建管理。
- 通用文件浏览器或完整终端模拟器。首发仅提供“在文件管理器打开”和“在外部终端打开”命令。
- 自建 Git 网络协议栈或替代 Git 的仓库格式实现。
- 将远程托管平台帐号作为使用基本 Git 功能的前置条件。

## 3. 信息架构与主窗口

### 主窗口布局

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ 仓库/最近项目   当前分支 ▼   ← 3  → 1       Fetch  Pull  Push    搜索/操作 │
├───────────────┬──────────────────────────────────────────────────────────┤
│ Git 导航       │ 当前视图                                                 │
│               │                                                          │
│ Changes       │                                                          │
│ Log           │                                                          │
│ Branches      │                                                          │
│ Stash         │                                                          │
│ Tags          │                                                          │
│ Repositories  │                                                          │
├───────────────┴──────────────────────────────────────────────────────────┤
│ 状态栏：仓库路径 | Git 版本 | 后台操作状态 | 错误与警告                   │
└──────────────────────────────────────────────────────────────────────────┘
```

- 顶栏左侧：仓库切换器、最近仓库和克隆/打开入口。
- 顶栏中心：当前分支选择器，以及相对上游的 ahead/behind 计数。
- 顶栏右侧：Fetch、Pull、Push、全局搜索/操作入口。
- 左侧导航：Changes、Log、Branches、Stash；有 Tag/Worktree 时按需显示对应入口。窄窗口可折叠为图标栏。
- 中央内容区：根据当前视图显示文件列表、提交图、分支列表或 Stash 列表。
- 详情区域：Diff、提交详情和冲突解决等内容采用可调整分栏；用户可拖动分隔线、隐藏次要面板。
- 状态栏：显示当前仓库、Git 操作进度和可操作错误；不得用状态栏替代需要用户处理的模态错误。

### 视图切换

- `Changes`：工作区及暂存区状态，默认打开仓库时显示。
- `Log`：提交图、提交列表、提交详情和文件差异。
- `Branches`：本地/远程分支、上游关系及批量分支操作。
- `Stash`：Stash 条目和应用/恢复操作。
- 仓库中没有某类对象时仍显示空状态和相关的 Git 操作入口，不显示营销式说明。
- 各视图保留筛选、排序、所选项和面板尺寸；切仓库时按仓库分别记忆。

## 4. 主要工作流与交互

### 4.1 打开仓库与克隆

- 启动页显示最近打开的仓库、打开目录和克隆仓库入口。
- 打开目录时向上查找 `.git`，支持工作树中的 `.git` 文件；若目录不是仓库，可选择初始化仓库或取消。
- 克隆表单包含 URL、目标目录、可选分支；显示 SSH/HTTPS 地址原样内容，凭据由系统 Git 凭据助手处理。
- 克隆完成后打开该仓库并检查 Git identity；缺失时提示设置 `user.name` 和 `user.email`，不阻断只读浏览。
- Git 不可用时提供查找/选择 Git 可执行文件入口，并显示检测到的版本。

### 4.2 Changes 与提交

Changes 主视图分成三个区域：

1. **Changes**：已暂存的更改。
2. **Unstaged Changes**：已跟踪文件的工作区改动。
3. **Untracked Files**：尚未纳入版本控制的新文件。

每项展示状态图标、文件名/相对路径、重命名两端（如适用）和差异摘要。冲突文件单独分组并置顶。支持按目录树或扁平列表显示，列表可排序和过滤。

- 单击文件在详情区打开 Diff；双击在外部编辑器打开。
- 文件级 Stage/Unstage 可通过工具栏、上下文菜单和快捷键执行。
- Diff 支持行内改动、新增/删除行、忽略空白切换、上一处/下一处改动、复制路径。
- 支持选择 Diff 区块（hunk）暂存或取消暂存；选择单行时扩展为完整可应用区块，无法独立应用时明确提示。
- Restore/Discard 只影响工作区，不改变 HEAD；操作前标明涉及的文件数量，并提供查看 Diff 的入口。
- 提交区包含提交消息输入框、选中更改统计、Amend、提交、提交并推送按钮。
- 默认提交所有已暂存变更；Ctrl/Cmd+K 沿用 IntelliJ 习惯，打开提交视图并选择当前活动变更集。若当前没有暂存内容，可按产品设置自动暂存所选文件，必须清楚展示实际提交范围。
- 可配置提交前检查（至少支持执行 Git hooks 的正常行为，不绕过 hooks）；hooks 失败时保留消息和选中状态。
- 提交成功后清空已提交变更选择並刷新 Log；提交失败不丟失消息或选中状态。
- Amend 模式明确提示将改写上一个本地提交；若上一提交已推送，提示后果。

### 4.3 Diff 与版本比较

- 文件 Diff 默认左右并排，可切换上下排列；左侧是基准版本，右侧是目标版本，标题明确标记版本来源。
- Changes 中比较 `HEAD ↔ 工作区` 或 `HEAD ↔ 暂存区`；可切换查看 staged 与 unstaged 差异。
- Log 中比较提交父版本与所选提交；可比较任意两个提交、分支或 Tag。
- 提供统一 Diff 工具栏：上一处/下一处改动、空白差异开关、复制路径、外部打开、面板方向。
- 二進制文件顯示類型、大小和版本信息，不嘗試作為文本解析。
- 大文件和超大 Diff 應保持界面響應，允許取消載入。

### 4.4 Log

- 上部为提交图和提交列表，分支、HEAD、Tag 和远端引用使用不同图标/标签；不能只依赖颜色区分。
- 列表列：圖、提交消息、作者、日期、短 SHA、引用標籤。可配置列和排序。
- 搜索/筛选：提交消息、作者、提交 SHA、路径、日期范围、当前分支/所有分支。
- 选中提交后，详情区显示完整消息、作者/提交者、时间、父提交、改动文件和 Diff。
- 右鍵操作：Copy SHA、Checkout、New Branch、Cherry-pick、Revert Commit、Reset Current Branch to Here、Compare With Current、Show Diff。
- Reset 按操作类型明确显示 `--soft`、`--mixed` 或 `--hard` 效果；Hard reset 显示将丢弃的工作区/暂存区变更并要求确认。
- Log 載入採分批追加；圖形在增量載入時保持連續且可滾動。

### 4.5 分支管理

- 当前分支选择器提供本地分支、远端分支和常用操作；Branches 视图提供可搜索的完整列表。
- 分组显示 Local、Remote、Recently Used；远端分支格式为 `remote/branch`，不能与本地同名分支混淆。
- 操作包括 Checkout、New Branch、Rename、Delete、Set Upstream、Compare、Merge into Current、Rebase Current onto Selected、Push。
- 新建分支可从当前 HEAD、所选分支或 Log 中所选提交开始，并可选择创建后立即切换。
- 删除已合并分支允许快速确认；删除未合并分支时显示未合并提交和保留该分支的替代操作。
- Checkout 遇到未提交变更时先检查是否会覆盖文件；可安全保留时允许切换，否则列出冲突文件并给出 Cancel/Stash/Force Checkout 选项。Force Checkout 需二次确认。
- ahead/behind 数据基于已知远端引用，显示其最后 Fetch 时间；提供 Fetch 刷新。

### 4.6 远端同步

- Fetch 不改变工作区；显示正在更新的远端、进度和新引用数量。
- Pull 设置策略：Merge、Rebase 或 Fast-forward only；操作菜单允许本次临时选择，不隐藏实际策略。
- Push 先顯示目標遠端/分支和即將推送的提交；非快進推送失败时保留錯誤輸出并提供 Fetch/Sync 入口。
- Force push 默认使用 `--force-with-lease`，将远端引用和本地引用显示给用户，需明确确认。
- 多远端仓库可以选择远端；若当前分支没有 upstream，Push/Pull 先提供设置 upstream 的流程。
- 网络错误、认证失败、Hook 拒绝和非快进错误要区分呈现，保留原始 Git 错误详情。

### 4.7 Merge、Rebase、Cherry-pick、Revert

- Merge/Rebase 对话框展示来源、目标、当前分支和工作区是否干净。
- 操作前若工作区不干净，提供取消或先 Stash；不得在用户未选择时自动丢弃改动。
- 发生冲突时跳转到冲突文件清单，保留正在进行的 Git 操作状态。
- 冲突全部解决后显示 Continue；可选 Abort 以中止当前 Merge/Rebase/Cherry-pick。
- Cherry-pick 可在 Log 中选择单个或多个提交，明确展示顺序。
- Revert 生成新的反向提交，不改写历史；在执行前以此语义描述操作。

### 4.8 冲突解决

- 冲突清单显示文件路徑和冲突状态；支持逐文件打开和解决全部非冲突区域。
- 三方視圖：左側 Current（當前分支/本地版本）、右側 Incoming（合併來源版本）、中央 Result（最終文件）。具體標籤按 Git 操作語境解釋，避免只寫 Yours/Theirs。
- 衝突塊操作：Accept Current、Accept Incoming、Accept Both、手工编辑；对已解决冲突可重新打开修改。
- 提供下一個/上一個衝突導航和剩餘衝突計數。
- 标记解决与 Git index 狀態同步；只有所有冲突都解决后才允许 Continue。
- Abort 顯示當前操作類型和可能影響；保留操作前未提交變更的規則與 Git 一致。

### 4.9 Stash

- Stash 列表顯示消息、建立時間、分支和涉及文件。
- 保存時可選擇包含未跟蹤文件，輸入消息；默認不隱藏未跟蹤文件。
- Apply 保留 Stash；Pop 成功後刪除該 Stash；發生衝突時保留 Stash 並進入衝突流程。
- 支持查看 Stash Diff、創建分支、刪除；刪除需確認。

## 6. 设置

### Git

- Git 可执行文件路径、自动检测、Git 版本。
- Git identity：`user.name`、`user.email`，标示其来源（system/global/local/worktree）。
- 默认远端、默认 Push 行为和 Pull 策略。
- Fetch pruning、子模塊遞歸等常用配置的可視化狀態；修改時說明對應配置鍵。
- SSH/HTTPS 認證交由 Git credential helper/SSH agent；客戶端不另存明文密碼。
- Git 操作环境变量或额外参数仅在高级设置中提供。

### 界面与键位

- Keymap 预设和逐项自定义；搜索操作名，显示冲突并允许重新分配。
- Diff 并排/上下方向、空白显示、文件列表扁平/树状。
- Log 默认范围和列可见性。
- 主題、字體和高對比使用 Viva 和目标平台能力实现；主窗口密度、面板关系、图标位置、选中/悬停反馈、分栏比例和可见操作以 Rebased 截图及检查点为基准，允许底层绘制差异，不允许信息架构或视觉层级改版。

## 7. 狀態、錯誤與資料安全

- 每个仓库只能有一个会修改该仓库的 Git 操作同时执行；读操作可以在不影响一致性的条件下并行。
- 長操作顯示階段、目標和取消入口。取消不保證回滾已完成的 Git 步驟，結果需重新讀取倉庫狀態。
- Git 命令失败时展示摘要、命令类型、退出码、可展开的标准错误输出，以及下一步可行操作。
- 对外部 Git 操作（如在终端执行后）监听文件系统变化并重新检查；视图提供手动刷新。
- 不把 Git stderr 中可能含凭据的内容写入普通日志；诊断导出前允许检查内容并遮蔽认证信息。
- 工作区未提交变更会在影响它的分支切换、Pull、Merge、Rebase、Reset 等操作前明确提示。
- 危险操作要呈现对象和效果，例如分支名、提交 SHA、远端 refspec、将丢弃的文件数量。
- 操作成功/失败后保留用户可恢复的上下文，例如提交消息、Log 选中位置和搜索条件。

## 8. 可訪問性與本地化

- 所有按钮、图标操作、分支状态和 Diff 标记提供可访问名称；不能只靠颜色表达 staged、冲突或 ahead/behind。
- 支持通过键盘完整操作列表、菜单、对话框、Diff 和冲突流程；焦点顺序符合视觉顺序。
- 字体缩放、系统高对比和屏幕阅读器标签列入正式验收。
- 首发界面支持中文与英文；Git 命令、路径和原始错误文本保持原样展示。

## 9. 非功能要求

- 启动后可先显示最近仓库和最近状态，再异步加载提交历史；单一大型仓库的 Log 加载不得冻结主界面。
- 文件狀態刷新採用事件觸發與批量更新，避免每個文件單獨啟動 Git 子進程。
- 支持 Windows、macOS、Linux 桌面环境；平台原生文件选择、凭据代理和快捷键标记符合系统习惯。
- 不以指定语言、UI 框架或 Git 绑定库作为产品需求。语言选择阶段需评估子进程/取消能力、文件监听、图形渲染、打包更新、无障碍、跨平台凭据和启动耗时。
- 使用仓库级测试验证文件状态、暂存区、提交、分支操作、冲突和失败恢复；测试不得依赖真实远端服务。

## 10. 首發驗收清單

- 新用户可打开或克隆仓库，并能辨认当前分支和远端同步状态。
- 修改/新增/刪除文件顯示在正確分組，文件 Diff 與 Git CLI 結果一致。
- 文件级和 hunk 级 Stage/Unstage 后，暂存与工作区差异分开正确显示。
- 提交成功后 Log 更新；Hook 失敗、identity 缺失或提交失败時不丟失消息和選中變更。
- 支持建立/切換分支、Fetch、Merge Pull、Rebase Pull、Push，以及 upstream 未配置時的引導。
- Merge/Rebase 衝突可在三方視圖解決、標記完成、Continue 或 Abort。
- Log 支持搜索、提交詳情、Diff、Cherry-pick、Revert 和受保護的 Reset。
- Stash 保存、查看、Apply、Pop 和衝突恢復可用。
- 快捷键预设可选、可搜索、可重映射；冲突被指出；视图焦点和文本输入不互相抢键。
- 有损操作均展示具体影响并等待确认；正常只读操作不被多余确认打断。
- Windows/macOS/Linux 至少完成倉庫打開、Git 定位、核心快捷鍵、Diff 和憑據委派的人工驗收。

## 11. 技术约束与 Rebased 对照基线

实现技术固定为 Go + Viva；Git 语义来自系统 Git CLI。Viva 绘制和输入遵守 `.claude/skills/building-with-viva/SKILL.md` 及 `docs/ARCHITECTURE.md`：绘制不做 I/O、不等待，后台结果通过收件箱、`Invalidator`、`OnWake` 回到窗口线程；控件使用 `ui.Tree` 命名；空闲时无轮询和定时器。任何无法直接复现的 Rebased 能力都要先登记差异、替代交互和验收标准。

Rebased 基线固定为 `D:\privateProject\rebased` 仓库 `master` 的 `245042348669114adb8e24e5b0fc0ce73763f3c4`（2026-10-28），并以对应 `screenshot.png`、README、Git 插件动作注册和默认产品插件清单作为基线材料。升级基线时记录新 SHA、截图和差异。视觉验收使用同尺寸截图和控件/区域清单，不要求像素级复刻 JetBrains 绘制引擎，但要求窗口区域、相对布局、密度、色彩层级、主要控件和交互结果一致。
